# QN85DD compatibility check

This guide prepares the port for **QN75QN85DDFXZA** with main firmware
**T-PTMDAKUC-0090-2130.0**. These two values were read from the owner's About
TV screen. A non-root diagnostic ran on this TV on 2026-10-23.

The [device profile](../profiles/qn75qn85ddfxza-2130.0.json) is at the
`preview-validated` stage. It permits fixed diagnostics, inventory, probe,
backup, preview, and guarded Home routing/restore operations. Arbitrary
commands and transfers and cleanup remain disabled. The Home button, one full
restart, and standby/wake now open Quiet Home. The owner's three selected app
logos are visible.

## Observed preflight

The SDB-reported model matched `QN75QN85DDFXZA`. The diagnostic observed
`Linux 5.4.249 armv7l GNU/Linux` and .NET runtime `6.0.9` using resolved CLR
files because the host did not support `--list-runtimes`. Both archive-route
file-capability checks and `tar --to-command` passed. The candidate Bixby
Promotion and QuickLaunch assemblies, selected native libraries, and package/key
registry files were visible to the SDK user. The selected registry tables had
the columns used by the original recipes. The private structured report is kept
under `.local/qn85dd-preflight.json` in the owner's checkout.

The temporary root check then ran `id` on this TV with authenticated UID/EUID 0.
Its staging was removed, and the original passwd/SDB key hashes were unchanged.
The private session record is under `.local/sessions/`. This establishes only
temporary access through the checked route; it did not by itself establish launcher
or cleanup compatibility. The profile's conservative 400-byte SDB inline cap
applies to the access path as well.

The fixed read-only root inventory observed Tizen `9.0.0`, a 32-bit process
environment, 554 application-registry rows, the four matching .NET framework
references, and the original main-operation Home handler and Home/startup
preferences all set to `com.samsung.tv.csfs`. The source API returned types
`13` and `14`; the owner identifies these as a PlayStation 5 on HDMI 1 and a
Nintendo Switch on HDMI 2. The PS5 input was later visibly tested; the Switch
is unplugged and remains unverified. The settings key registry contains **two** `com.samsung.tv.quicklaunch` /
`XF86More` rules, so the original settings-bridge recipe's one-row guard would
stop on this TV. The observed `pisa-service` and `canalysis-service` units have
the stop-marker conditions described in the case study, but no cleanup target
has been enabled from that observation.

The four matching framework DLLs were transferred through the authenticated
agent with per-file checksums into ignored `.local/tv-framework/`; SDB's direct
pull was denied. Quiet Home, QuickLaunch, and the read-only Probe compile locally
against those references. Probe confirmed the original Home handler and returned
the two source types above. Subsequent visible checks covered the PS5 input,
selected app launches, and settings controls. Cleanup remains untested; one
full restart with the adjusted Start Screen Options opened Quiet Home.
The ARM ABI has not been independently measured, although the preview launcher
runs on the TV.

A fixed snapshot saved three consistent SQLite database copies and the
original Bixby Promotion package under a unique backup name on the TV. The
desktop copy under ignored `.local/backups/` was checksum-verified; each SQLite
copy passed `PRAGMA quick_check`. The original assembly, native image, registry
flags, and Home/startup preferences were recorded. The preview installer
replaced the candidate assembly and added package assets, preserving the
original executable mode and SMACK label. A matching restore script was saved
on the TV before installation. The owner confirmed that Quiet Home appears and
that remote navigation between its sections works. The PlayStation 5 card
switched to HDMI 1 with picture and sound. Volume, Sound (mute), Advanced,
Network, and Controllers responded from Quiet Home's Settings page. The owner
also confirmed that the YouTube, Netflix, and Prime Video shortcuts opened the
correct apps. Before routing was changed, the Home button still opened Samsung
Home after leaving the preview. The Nintendo Switch input remains unverified
because the console is unplugged. Quiet Home itself has no menu or selection
sound effects; silence while moving between cards is expected.

The initial app catalog used the repository's text-only placeholder art. The
local artwork fetcher downloaded Netflix, YouTube, and Prime Video assets from
the [documented sources](../launcher/artwork-sources.json) into ignored paths.
A fixed artwork snapshot copied the live catalog on the TV and then to the
desktop before the update. The installer kept the launcher assembly and app
IDs unchanged, replaced the catalog, and added three local artwork files with
per-file checksum checks. The owner confirmed that all three logos appear in
both the dock and Apps page. The Nintendo Switch input remains unverified.

After the visible checks, the guarded routing script verified that the
installed assembly and the three original Home/startup selectors matched the
saved evidence. It saved its inverse before assigning Quiet Home. An
independent probe and preference readback confirmed all three new selectors.
The owner confirmed that the Home button opens Quiet Home. On the first full
restart, the screen stayed black for over 30 seconds; pressing Home opened
Quiet Home. The owner then turned on **Auto Open Last App** and turned off
**Autorun Samsung TV Plus** in Start Screen Options, leaving **Start with
Smart Hub Home** on. The next full restart opened Quiet Home automatically
without pressing Home. This is one successful restart with the combined
setting changes; it does not isolate which setting resolved the black screen.
The owner then put the TV in standby with a quick Power press and woke it;
Quiet Home appeared without pressing Home. The `preview-validated` gate accepts
only fixed commands for this exact model and firmware; it rejects arbitrary
execution/transfers and cleanup.
Raw inventory, probe, and preview session details remain under ignored
`.local/sessions/`.

A read-only check after the initial black-screen restart found the Quiet Home assembly unchanged,
the Home/startup selectors still assigned to it, and a running app process
launched with `cold_booting` and a background-launch argument. This shows the
app started during boot; it does not establish why its window was not visible.
The PS5 was powered on and the black screen showed no HDMI or No Signal
message. Samsung's [Start Screen Option guide](https://www.samsung.com/in/support/tv-audio-video/how-to-enable-or-disable-the-start-screen-option-on-your-samsung-smart-tv/)
says “Start with Smart Hub Home” governs whether Home or the last source is
shown at power-on. The owner found it on. No launcher or package flags were
changed to address the black screen.

## Staged commands and recovery

The fixed commands below require the exact profile and firmware, the TV's
address, and the computer address configured in Developer Mode. Use a new
backup name for a new installation attempt. Keep the TV and desktop backup
copies; the commands refuse to overwrite them. Building the preview requires
the .NET 6 SDK and the four private framework references already obtained from
that TV under `.local/tv-framework/`.

```powershell
$tvIp = (Read-Host "TV IPv4 address").Trim()
$pcIp = (Read-Host "Computer IPv4 address entered on the TV").Trim()
$phase = "home-01"
$tvArgs = @("--host", $tvIp, "--callback-host", $pcIp,
  "--sdb", "C:\tizen-studio\tools\sdb.exe",
  "--profile", "profiles/qn75qn85ddfxza-2130.0.json",
  "--firmware", "T-PTMDAKUC-0090-2130.0")
py -3 tools/tv.py @tvArgs snapshot $phase
py -3 tools/tv.py @tvArgs backup-pull $phase
py -3 tools/build.py launcher --framework .local/tv-framework
tar -czf .local/package-preview.tar.gz -C .local/package .
py -3 tools/tv.py @tvArgs preview-install $phase
```

Verify the visible preview before routing Home. `preview-launch` reopens it
after an app or input returns to Samsung Home. Once the remote, HDMI, sound,
native settings, and selected apps work, `home-route` assigns the Home and
startup selectors and saves its inverse on the TV:

```powershell
py -3 tools/tv.py @tvArgs preview-launch $phase
py -3 tools/tv.py @tvArgs home-route $phase
```

The selected app artwork can be added after the visible preview and Home tests.
`fetch_artwork.py` writes publisher images and the customized catalog only to
ignored local paths. Use a new artwork backup name, copy that backup to the
computer, then install the fixed resource update:

```powershell
py -3 tools/fetch_artwork.py --app Netflix --app YouTube --app "Prime Video"
$artPhase = "artwork-01"
py -3 tools/tv.py @tvArgs artwork-snapshot $artPhase
py -3 tools/tv.py @tvArgs artwork-backup-pull $artPhase
py -3 tools/tv.py @tvArgs artwork-install $artPhase
```

Verify the logos on the TV. If the catalog needs restoring, use
`py -3 tools/tv.py @tvArgs artwork-restore $artPhase`; it checks the installed
file hashes before replacing the catalog and removing those three image files.

If Home routing needs to be undone, restore the selectors first. The second
command restores the original candidate assembly while leaving the added
preview resources inert. The inverse scripts compare live state with the saved
snapshot and stop on unrelated drift:

```powershell
py -3 tools/tv.py @tvArgs home-restore $phase
py -3 tools/tv.py @tvArgs preview-restore $phase
```

The exact TV used a private phase name and private host addresses, which are
intentionally absent from this public guide. Its Home-button test and one full
restart with the adjusted Start Screen Options passed. Standby/wake also returned
to Quiet Home. The separate artwork update passed on-device checks and the
owner's visual check. Running the restore commands remains untested.

## Prepare the computer and TV

Run the check from a computer connected to the **same local network as the
TV**. A remote cloud workspace cannot directly reach the TV's local address.

The computer needs:

- Python 3.12 or later.
- Samsung's SDB tool, installed separately through the supported
  [Tizen SDK CLI installer](https://samsungtizenos.com/tools-download/).
- This updated Quiet Tizen checkout.

The diagnostic command requires no .NET SDK, compiled root payload, or launcher
build. Open a terminal in the checkout's top-level directory.

Use Samsung's [Developer Mode connection instructions](https://developer.samsung.com/smarttv/develop/getting-started/using-sdk/tv-device.html):

1. Open Smart Hub, then Apps and App Settings.
2. Enter `12345` with the remote or its on-screen number keypad.
3. Turn Developer Mode on.
4. Enter the computer's local IPv4 address as the host computer address.
5. Confirm and restart the TV.

Menu labels can vary. Read the TV's local IPv4 address from its network settings.
The TV address and computer address serve different purposes; enter each in the
place specified below.

On a compact Samsung Smart Remote without physical number keys, press its
`123`/Number or combined Settings/Number/Color button while App Settings is
open. If a row of shortcuts appears, select `123`, then use the directional
pad and Select button to enter `1`, `2`, `3`, `4`, `5`; choose Done if shown.
Samsung documents the [on-screen number pad](https://developer.samsung.com/smarttv/design/input-methods.html).

### Windows preparation

1. Install [Python for Windows](https://www.python.org/downloads/windows/) if
   needed. Open PowerShell and run `py -3 --version`; the version must be 3.12
   or later. If only `python` is available, use `python` instead of `py -3` in
   the commands below.
2. Download the official
   [Tizen SDK CLI Windows 64-bit installer](https://download.tizen.org/sdk/Installer/tizen-sdk_10.0/web-cli_Tizen_SDK_10.0_windows-64.exe).
   Run it and choose `C:\tizen-studio` as the installation directory.
3. Verify the tool in PowerShell:

   ```powershell
   & "C:\tizen-studio\tools\sdb.exe" version
   ```

4. Connect the computer to the TV's network. Run `ipconfig` in PowerShell and
   find the IPv4 address of the active Wi-Fi or Ethernet adapter. Enter that
   computer address in the TV's Developer Mode settings, as described above.
5. Extract the updated Quiet Tizen ZIP. In File Explorer, open the `quiet-tizen`
   folder that contains `README.md` and `tools`. Type `powershell` in the address
   bar and press Enter to open PowerShell in that folder.

The [current SDK installation documentation](https://github.com/Samsung/tizen-docs/blob/master/docs/sdk-tools/baseline-sdk/setup/install-sdk.md)
supports the CLI installer. The [SDB documentation](https://github.com/Samsung/tizen-docs/blob/master/docs/sdk-tools/baseline-sdk/common-tools/smart-development-bridge.md)
places SDB in the SDK's `tools` directory. This diagnostic does not need a TV
extension, emulator, signing certificate, or .NET compiler.

## Run the diagnostic

Replace `TV_LAN_IP` with the TV's address. Keep the profile and firmware values
exactly as shown for this TV. Run this as one line on macOS or Linux:

```sh
python3 tools/tv.py --host TV_LAN_IP --profile profiles/qn75qn85ddfxza-2130.0.json --firmware T-PTMDAKUC-0090-2130.0 doctor --report .local/qn85dd-preflight.json
```

On Windows, paste this PowerShell helper. Enter the TV address and the computer
address when prompted. The computer address must match the one entered in the
TV's Developer Mode settings:

```powershell
$tvIp = (Read-Host "TV IPv4 address").Trim()
$pcIp = (Read-Host "Computer IPv4 address entered on the TV").Trim()
py -3 tools/tv.py --host $tvIp --callback-host $pcIp --sdb "C:\tizen-studio\tools\sdb.exe" --profile profiles/qn75qn85ddfxza-2130.0.json --firmware T-PTMDAKUC-0090-2130.0 doctor --report .local/qn85dd-preflight.json
```

If the SDK is installed elsewhere, change only the path after `--sdb`.
The helper can return exit code 2 when a prerequisite is not established;
return the report even if some checks are marked incomplete. If the command
stops before creating a report, return its error text.

To open the report's folder after it is created:

```powershell
explorer.exe .local
```

If SDB is installed in a location the tool does not find, add
`--sdb "ABSOLUTE_PATH_TO_SDB"` **before** `doctor`. On Windows this points to
`sdb.exe`. If the computer selects the wrong network interface, add
`--callback-host COMPUTER_LAN_IP` before `doctor`, replacing the placeholder
with the same local computer address configured in Developer Mode.

The helper connects only to the supplied TV address. It reads fixed diagnostic
fields through the existing SDB transport. It does not obtain root or change
persistent TV configuration. The transport can create temporary gate directories
and stage temporary command scripts.

## Review the report

The report is saved to `.local/qn85dd-preflight.json`. It records:

| Area | Evidence sought |
|---|---|
| Identity | Observed SDB model and declared About TV firmware |
| Runtime | Installed kernel, architecture, and .NET runtime evidence |
| Access prerequisites | Relevant file capabilities and archive-tool support |
| Launcher prerequisites | Candidate application files and native libraries |
| Configuration layout | Selected database schemas, where readable |

The report contains selected compatibility fields. It omits network addresses,
serial numbers, account identifiers, and raw diagnostic logs. Partial results are
saved when possible; unavailable or denied checks remain explicit. A missing
field requires investigation and does not mean its value matches the U8000F.

Return this report for the next port iteration. It identifies which components
can be reused and which need adaptation. Successful diagnostics establish
preflight observations; launcher behavior still requires building against the
actual TV libraries and testing on the TV.

## Why this access route is being investigated

The [upstream compatibility table](https://github.com/chris-ritsen/samsung-tv-root#tv-compatibility)
reports archive-launcher root access on a **QN55S90DAFXZA** using the same main
firmware string, `T-PTMDAKUC-0090-2130.0`. The associated
[S90D device record](https://github.com/splitcipher/couchroot/blob/main/docs/lab/devices/s90d/persistence.md)
documents root identity and cleanup checks. These are observations on another
model; they make this route worth checking without establishing QN85DD support.

That S90D record also reports rejection of a 495-byte inline SDB request and
success after staging it. This profile therefore uses a conservative **400-byte
inline request limit**. It is a computer-side transport setting, not a measured
hardware limit for this TV or evidence that root will work.

The QN85DD profile keeps cleanup targets unspecified until their effects can
be checked on this device. The `0090` component of the displayed firmware is
insufficient to infer behavior from another model.
